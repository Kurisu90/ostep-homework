
# 總覽

`vsfs_zh.py` 是 `vsfs.py` 的中文版本，功能完全相同，用來觀察檔案系統在
各種操作發生時，磁碟上的狀態如何跟著改變。模擬一開始，檔案系統只有一個
空的根目錄；隨著模擬進行，程式會執行各種操作，慢慢改變檔案系統在磁碟上
的狀態。

可能發生的操作有：

- mkdir()：建立一個新目錄
- creat()：建立一個新的（空）檔案
- open()、write()、close()：對某個檔案附加（append）一個資料區塊
- link()：對某個檔案建立一個硬連結（hard link）
- unlink()：移除某個檔案的連結（若連結數歸零，就把檔案真正刪除）

要理解這個作業如何運作，必須先了解這個檔案系統在磁碟上的狀態是怎麼
表示的。檔案系統的狀態是透過印出四種不同資料結構的內容來呈現：

- inode 點陣圖：標示哪些 inode 已被配置
- inode 內容：所有 inode 及其內容的表格
- 資料點陣圖：標示哪些資料區塊已被配置
- 資料區塊：各個資料區塊的內容

點陣圖應該很容易理解：1 代表對應的 inode 或資料區塊已被配置，0 代表
該 inode 或資料區塊是空閒的。

每個 inode 有三個欄位：第一個欄位標示檔案的類型（例如 f 代表一般
檔案，d 代表目錄）；第二個欄位標示屬於這個檔案的資料區塊（在這裡，
檔案要嘛是空的，此時位址欄位會是 -1，要嘛剛好佔一個區塊，此時位址欄位
會是一個非負整數）；第三個欄位顯示這個檔案或目錄的參照計數（reference
count）。舉例來說，以下這個 inode 是一個一般檔案，內容是空的（位址欄位
為 -1），而且在檔案系統中只有一個連結：

```sh
  [f a:-1 r:1]
```

如果這個檔案配置了一個資料區塊（假設是區塊 10），就會顯示成：

```sh
  [f a:10 r:1]
```

如果之後有人對這個 inode 建立了一個硬連結，就會變成：

```sh
  [f a:10 r:2]
```

最後，資料區塊裡存放的內容，可能是使用者資料，也可能是目錄資料。如果
存放的是目錄資料，區塊裡的每一筆項目都是 (name, inumber) 的形式，也就
是（名稱, inode 編號）；name 是檔案或目錄的名稱，inumber 則是該檔案的
inode 編號。因此，假設根目錄的 inode 編號是 0，一個空的根目錄看起來
會像這樣：

```sh
  [(.,0) (..,0)]
```

如果我們在根目錄底下加入一個檔案 "f"，並且配置到 inode 編號 1，根目錄
的內容就會變成：

```sh
  [(.,0) (..,0) (f,1)]
```

如果某個資料區塊存放的是使用者資料，就只會顯示區塊裡的單一字元，例如
"h"；如果這個區塊是空的、還沒被配置，就只會顯示一對空括號（[]）。

因此，整個檔案系統會像這樣呈現：

```sh
inode 點陣圖 11110000
inode 內容   [d a:0 r:3] [f a:1 r:1] [f a:-1 r:1] [d a:2 r:2] [] ...
資料點陣圖   11100000
資料區塊     [(.,0) (..,0) (y,1) (z,2) (f,3)] [u] [(.,3) (..,0)] [] ...
```

這個檔案系統有 8 個 inode、8 個資料區塊。根目錄除了 "." 和 ".." 之外，
還有三筆項目，分別對應 "y"、"z"、"f"。查看 inode 1 可以發現 "y" 是一個
一般檔案（類型 f），配置了一個資料區塊（位址 1）；在資料區塊 1 裡，
存放的正是檔案 "y" 的內容："u"。我們也可以看到 "z" 是一個空的一般檔案
（位址欄位為 -1），而 "f"（inode 編號 3）是一個空的目錄。從點陣圖也
可以看出，inode 點陣圖的前四個項目已被標示為已配置，資料點陣圖的前三個
項目也是如此。

模擬器支援以下旗標：

```sh
prompt> ./vsfs_zh.py -h
Usage: vsfs_zh.py [options]

Options:
  -h, --help            show this help message and exit
  -s SEED, --seed=SEED  隨機種子
  -i NUMINODES, --numInodes=NUMINODES
                        檔案系統中的 inode 數量
  -d NUMDATA, --numData=NUMDATA
                        檔案系統中的資料區塊數量
  -n NUMREQUESTS, --numRequests=NUMREQUESTS
                        要模擬的請求數量
  -r, --reverse         不列印狀態，改成列印操作內容
  -p, --printFinal      列印最終的檔案／目錄清單
  -c, --compute         幫我計算答案
```

（`-h, --help` 這一行的說明文字是 optparse 套件本身內建、寫死的英文
字串，程式並未對它做在地化，所以執行 `-h` 時仍會看到這一行英文；其餘
所有旗標的說明都已經是中文。）

一般的用法是指定一個隨機種子（藉此產生不同的題目）以及要模擬的請求
數量。在這種預設模式下，模擬器會在每一步印出檔案系統目前的狀態，並
問你：是哪一個操作，把檔案系統從前一個狀態變成了目前這個狀態？舉例
來說：

```sh
prompt> ./vsfs_zh.py -n 6 -s 16
參數 seed（隨機種子） 16
參數 numInodes（inode 數量） 8
參數 numData（資料區塊數量） 8
參數 numRequests（模擬請求數量） 6
參數 reverse（反向模式） False
參數 printFinal（列印最終清單） False

```

在這種模式下，模擬器只會顯示一連串的狀態，然後問你是哪些操作造成了
這些變化。加上 `-c` 旗標重新執行一次，就能看到答案：檔案 "/y" 被建立，
接著附加了一個資料區塊上去；然後 "/m" 對 "/y" 建立了一個硬連結；再來
"/m" 被 unlink 移除；接著建立了檔案 "/z"；最後建立了目錄 "/f"：

```sh
prompt> ./vsfs_zh.py -n 6 -s 16 -c
```

你也可以用「反向模式」（加上 `-r` 旗標）執行模擬器，這時會改成印出
操作內容，讓你反過來預測每個操作會讓狀態變成什麼樣子：

```sh
prompt> ./vsfs_zh.py -n 6 -s 16 -r
參數 seed（隨機種子） 16
參數 numInodes（inode 數量） 8
參數 numData（資料區塊數量） 8
參數 numRequests（模擬請求數量） 6
參數 reverse（反向模式） True
參數 printFinal（列印最終清單） False

初始狀態

inode 點陣圖  10000000
inode 內容   [d a:0 r:2][][][][][][][]
資料點陣圖    10000000
資料區塊     [(.,0) (..,0)][][][][][][][]

creat("/y");

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？

fd=open("/y", O_WRONLY|O_APPEND); write(fd, buf, BLOCKSIZE); close(fd);

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？

link("/y", "/m");

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？

unlink("/m");

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？

creat("/z");

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？

mkdir("/f");

  檔案系統目前狀態為何（inode 點陣圖、inode 內容、資料點陣圖、資料區塊）？
```

還有幾個旗標可以控制模擬的其他細節，包括 inode 的數量（`-i`）、資料
區塊的數量（`-d`），以及是否要在最後列印出檔案系統裡所有檔案與目錄的
清單（`-p`）。
