
# 概觀：`generator_zh.py`

`generator_zh.py` 是 `generator.py` 的中文版本，功能完全相同，只是把
所有的說明文字、命令列選項說明，以及執行時印出的訊息都換成了中文，
方便你理解如何用它產生小型的 C 程式來練習 `fork`。

這個工具可以讓你建立一些會用不同方式呼叫 `fork` 的小型 C 程式，藉此
更加了解 `fork` 是怎麼運作的。

一個簡單的用法如下：
```sh
prompt> ./generator_zh.py -n 1 -s 0
```

執行之後，你會看到一個隨機產生的 C 程式。在這個例子中，你會看到類
似這樣的內容（NOTE：這段輸出是產生出來、要交給 gcc 編譯的 C 原始碼，
其中的程式碼與註解本來就是英文，並非本工具的中文介面文字，因此維持
原樣不做翻譯）：

```c
#include <assert.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/time.h>
#include <sys/wait.h>
#include <unistd.h>

void wait_or_die() {
    int rc = wait(NULL);
    assert(rc > 0);
}

int fork_or_die() {
    int rc = fork();
    assert(rc >= 0);
    return rc;
}

int main(int argc, char *argv[]) {
    // process a
    if (fork_or_die() == 0) {
        sleep(6);
        // process b
        exit(0);
    }
    wait_or_die();
    return 0;
}

```

我們稍微理解一下這段程式碼。第一部分（從最上面到 `main()` 開始之
前）每個產生出來的 C 程式都會包含。`wait_or_die()` 與 `fork_or_die()`
這兩段程式碼，只是分別包了一層 `wait` 與 `fork` 系統呼叫，正常情況下
會成功，如果偵測到錯誤（透過檢查存放在 `rc` 裡的回傳值）就會透過
`assert()` 讓程式結束。當失敗時直接結束程式是可以接受的做法（雖然不
是任何情況下都適用，但這裡沒問題），用這兩個包裝函式可以讓 `main()`
裡的程式碼更容易閱讀。

補充說明：如果你還不熟悉 `assert()`，它是一個巨集（macro），單純檢查
你傳給它的運算式是否為真。如果條件為真，`assert()` 什麼事都不做，程
式繼續往下執行；如果條件為假，這個行程就會結束。

程式真正有趣的部分，也就是會隨著不同亂數種子而改變的部分，在
`main()` 裡面。這裡我們可以看到主行程（在此我們稱它為「行程 a」，或
簡稱 `a`）啟動、呼叫 `fork_or_die()` 建立另一個行程，然後（透過呼叫
`wait_or_die()`）等待那個行程結束。

子行程（稱為「b」）則只是睡了一段時間（這裡是 6 秒），然後就結束了。

接下來，你的挑戰就是預測這個程式實際執行時輸出會長什麼樣子。跟之前
一樣，只要加上 `-c` 旗標，就能直接得到結果：

```sh
prompt> ./generator_zh.py -n 1 -s 0 -c
  0 a+
  0 a->b
  6      b+
  6      b-
  0 a+
  0 a->b
  6 a<-b
prompt>
```

輸出的讀法如下：第一欄顯示的是事件發生的時間。在這個例子裡，時間
0 發生了兩個事件：首先，行程 a 開始執行（顯示為 `a+`）；接著，a 呼叫
fork 建立了 b（顯示為 `a->b`）。

然後，b 開始執行，並依照程式碼馬上睡了 6 秒。睡眠結束後，b 印出它已
經被建立（`b+`），但接下來也沒做別的事，直接就結束了，這也顯示出來
了（`b-`）。輸出中這兩者看起來都發生在時間 6；但實際上我們知道
`b+` 一定發生在 `b-` 之前。

最後，當 b 結束之後，父行程 a 裡的 `wait_or_die()` 呼叫就會返回，並
印出最後一行（`a<-b`）表示這件事發生了。

至於為什麼 `0 a+` 與 `0 a->b` 會在輸出中出現兩次，這其實是真實可以觀
察到的現象，而不是這份翻譯或模擬器的錯誤：C 標準函式庫的 `printf` 在
輸出並非連到終端機（terminal）時，預設會採用「full buffering」，也就
是先把輸出暫存在緩衝區裡，不會馬上真的寫出去。當父行程呼叫
`fork()` 建立子行程時，子行程會複製一份父行程當時「尚未真正輸出」的
緩衝區內容；之後子行程呼叫 `exit()` 時，會把自己那份緩衝區內容（包含
繼承來的舊內容，加上自己新印出的內容）一起真正寫出去，於是這些內容
就出現了第一次；等到父行程自己最後結束、把它自己那份緩衝區內容也真
正寫出去時，同樣的舊內容就又出現了一次。這正是課本內文中提到的
「fork 與緩衝式 I/O」互動的經典例子，值得你仔細想一想。

有幾個旗標可以控制隨機產生出來的程式碼，分別是：
* `-s SEED` - 不同的隨機種子會產生不同的程式
* `-n NUM_ACTIONS` - 一個程式要包含多少個動作（`fork`、`wait`）
* `-f FORK_CHANCE` - 加入一次 `fork()` 的機率，範圍是 1 到 99（百分比）
* `-w WAIT_CHANCE` - 同上，但是針對 `wait()`（當然，要有尚未處理的
  `fork` 才可能呼叫它）
* `-e EXIT_CHANCE` - 同上，但是針對行程 `exit` 的機率
* `-S MAX_SLEEP_TIME` - 在程式碼中加入 `sleep` 時，選用的最長睡眠時間

另外還有幾個旗標，用來控制程式碼要輸出到哪些 C 檔案：
* `-r READABLE` - 這是給你看的檔案（特別針對可讀性做過最佳化）
* `-R RUNNABLE` - 這是真正會被編譯並執行的檔案；內容跟上面那份幾乎
  一樣，只是額外加上了印出訊息之類的程式碼

最後還有一個旗標 `-A`，可以讓你精確指定要產生的程式內容。例如：

```sh
prompt> ./generator_zh.py -A "fork b,1 {} wait"
```

對應產生的 C 程式碼（同樣維持英文，理由同上）：
```c
int main(int argc, char *argv[]) {
    // process a
    if (fork_or_die() == 0) {
        sleep(1);
        // process b
        exit(0);
    }
    wait_or_die();
    return 0;
}
```

這個指令會建立預設的行程（「a」），它會 fork 出「b」，「b」睡了 1
秒之後就不再做別的事情；與此同時，「a」則等待「b」結束。

也可以組合出更複雜的例子，例如：
* `-A "fork b,1 {} fork c,2 {} wait wait"` - 行程「a」建立了兩個行程
  「b」與「c」，然後等待兩者都結束
* `-A "fork b,1 {fork c,2 {} fork d,3 {} wait wait} wait"` - 行程
  「a」建立「b」，然後等它結束；而「b」則建立了「c」與「d」，並且等
  待它們都結束

讀完這份說明並完成對應的作業題目，你應該就能對 `fork` 有更完整的理
解了。
