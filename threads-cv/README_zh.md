
# 總覽

> 本文件為 `README.md` 的繁體中文翻譯版本。對應的原始檔已翻譯為以 `_zh` 結尾的程式檔，建置檔則是 `Makefile_zh`；若要建置英文原始版本，請仍使用 `make` 與原始檔名。

這份作業讓你探索一些真實的程式碼，這些程式碼使用鎖（lock）與條件變數（condition variable）來實作本章所討論的各種生產者／消費者佇列（producer/consumer queue）形式。你將檢視這些實際的程式碼，在各種不同的設定下執行它，並藉此學習哪些做法可行、哪些不可行，以及其他相關的細節。

這些不同版本的程式碼，對應著「解決」生產者／消費者問題的不同方式。其中大部分是錯誤的，只有一個是正確的。請閱讀該章節，以了解更多關於生產者／消費者問題本身，以及這些程式碼大致上在做什麼。

第一步是下載程式碼，並輸入 `make -f Makefile_zh` 來建置所有中文化版本。你應該會看到四個程式：
- `main-one-cv-while_zh.c`：使用單一條件變數解決生產者／消費者問題。
- `main-two-cvs-if_zh.c`：相同，但使用兩個條件變數，並以 `if` 來檢查是否要睡眠等待。
- `main-two-cvs-while_zh.c`：相同，但使用兩個條件變數，並以 `while` 來檢查是否要睡眠等待。這是正確的版本。
- `main-two-cvs-while-extra-unlock_zh.c`：相同，但在填入（fill）與取出（get）程式前後多加了一次解鎖與重新上鎖。

另外，也建議你看看 `pc-header_zh.h`，其中包含了這些不同主程式共用的程式碼；以及 `Makefile_zh`，才能正確建置程式碼。

每個程式都接受下列旗標：
- `-l <每個生產者要產生的項目數量>`
- `-m <生產者/消費者共用緩衝區的大小>`
- `-p <生產者的數量>`
- `-c <消費者的數量>`
- `-P <睡眠字串：生產者在執行過程中各個時間點應該睡眠多久>`
- `-C <睡眠字串：消費者在執行過程中各個時間點應該睡眠多久>`
- `-v [ 詳細旗標：追蹤目前發生的狀況並印出來 ]`
- `-t [ 計時旗標：計算整個執行時間並印出總時間 ]`

前四個參數相對容易理解：`-l` 指定每個生產者要迴圈執行幾次（也就是每個生產者要產生多少筆資料），`-m` 控制共用緩衝區的大小（必須大於或等於 1），而 `-p` 和 `-c` 則分別設定生產者與消費者的數量。

比較有趣的是這兩個睡眠字串，一個給生產者用、一個給消費者用。這些旗標可以讓你使每個執行緒在執行過程中的特定時間點睡眠，藉此切換到其他執行緒執行；透過這種方式，你可以實驗每一種解法，或許能藉此找出特定的問題，或是研究生產者／消費者問題的其他面向。

字串的指定方式如下。舉例來說，如果有三個生產者，該字串就應該以冒號分隔，分別指定各個生產者的睡眠時間。這三個生產者的睡眠字串大概會長這樣：

```sh
  sleep_string_for_p0:sleep_string_for_p1:sleep_string_for_p2
```

而每一個睡眠字串本身，則是以逗號分隔的清單，用來決定在程式碼中每個睡眠點要睡多久。為了更清楚地理解這種每個生產者或消費者各自的睡眠字串，讓我們看看 `main-two-cvs-while_zh.c` 中的程式碼，特別是生產者的部分。在這段程式碼片段中，生產者執行緒會迴圈執行一段時間，透過呼叫 `do_fill()` 把元素放入共用緩衝區。在這個填入程序前後，有一些等待與發出信號（signal）的程式碼，用來確保生產者嘗試填入時緩衝區不是滿的。詳細內容請參閱該章節。

```c
void *producer(void *arg) {
    int id = (int) arg;
    int i;
    for (i = 0; i < loops; i++) {   p0;
        Mutex_lock(&m);             p1;
        while (num_full == max) {   p2;
            Cond_wait(&empty, &m);  p3;
        }
        do_fill(i);                 p4;
        Cond_signal(&fill);         p5;
        Mutex_unlock(&m);           p6;
    }
    return NULL;
}
```

從程式碼中可以看到，有好幾個標記為 p0、p1 等的位置。這些位置就是程式碼可以被放入睡眠的地方。消費者的程式碼（此處未列出）也有類似的等待點（c0 等等）。

為生產者指定睡眠字串很簡單：只要依序指出生產者在 p0、p1、...、p6 這幾個位置各要睡眠多久即可。舉例來說，字串 `1,0,0,0,0,0,0` 表示生產者要在 p0 這個標記處（也就是取得鎖之前）睡眠 1 秒，之後每次迴圈執行時都不再睡眠。

現在讓我們來看看執行其中一個程式的輸出結果。首先，假設使用者只用一個生產者和一個消費者來執行，並且完全不加入任何睡眠（這是預設的行為）。在這個範例中，緩衝區大小設為 2（`-m 2`）。

首先，讓我們先建置程式碼：

```sh
prompt> make -f Makefile_zh
gcc -o main-two-cvs-while_zh main-two-cvs-while_zh.c -Wall -pthread
gcc -o main-two-cvs-if_zh main-two-cvs-if_zh.c -Wall -pthread
gcc -o main-one-cv-while_zh main-one-cv-while_zh.c -Wall -pthread
gcc -o main-two-cvs-while-extra-unlock_zh main-two-cvs-while-extra-unlock_zh.c -Wall -pthread
```

現在我們可以執行看看：

```sh
prompt> ./main-two-cvs-while_zh -l 3 -m 2 -p 1 -c 1 -v
```

在描述這個簡單範例中發生的事情之前，我們先來了解輸出左側呈現共用緩衝區的方式。一開始緩衝區是空的（空的位置以 `---` 表示，兩個空位顯示為 `[*--- --- ]`）；輸出同時也顯示緩衝區中項目的數量（`num_full`），一開始為 0。接著，在 P0 放入一個值之後，狀態變成 `[u 0 f--- ]`（`num_full` 也變成 1）。你可能也會注意到幾個額外的標記：`u` 標記顯示 `use_ptr` 所在的位置（也就是下一個要消費值的消費者會從這裡取值）；同樣地，`f` 標記顯示 `fill_ptr` 所在的位置（也就是下一個生產者要生產值的位置）。當你看到 `*` 標記時，代表 `use_ptr` 和 `fill_ptr` 剛好指向同一個位置。

在輸出右側，你可以看到每個生產者與消費者即將執行的步驟追蹤。舉例來說，生產者先取得鎖（`p1`），接著因為緩衝區還有空位，就把一個值放進去（`p4`）。之後它會繼續執行，直到釋放鎖的位置（`p6`），然後再嘗試重新取得鎖。在這個範例中，換成消費者取得了鎖並消費了這個值（`c1`、`c4`）。你可以進一步研究這份追蹤紀錄，來理解在只有一個生產者與一個消費者的情況下，這個生產者／消費者解法是如何運作的。

現在讓我們加入一些暫停，藉此改變追蹤紀錄的行為。這次，假設我們想讓生產者睡眠，好讓消費者可以先執行。我們可以這樣做：

```sh
prompt> ./main-two-cvs-while_zh -l 1 -m 2 -p 1 -c 1 -P 1,0,0,0,0,0,0 -C 0 -v

結果如下：
```

如你所見，生產者執行到程式碼中的 p0 標記處，然後從它的睡眠規格中取出第一個值，在這個例子中是 1，因此在嘗試取得鎖之前，會先睡眠 1 秒。這樣一來，消費者就有機會先執行，取得鎖之後卻發現佇列是空的，於是就進入睡眠（並釋放鎖）。生產者接著（最終）開始執行，後續的流程就如你所預期的那樣進行。

請注意：每個生產者與消費者都必須指定一個睡眠規格。因此，如果你建立了兩個生產者與三個消費者（`-p 2 -c 3`），就必須為每一個都指定睡眠字串（例如：`-P 0:1` 或 `-C 0,1,2:0:3,3,3,1,1,1`）。睡眠字串的長度可以比程式碼中睡眠點的數量還短；其餘未指定的睡眠位置預設會被初始化為 0。
