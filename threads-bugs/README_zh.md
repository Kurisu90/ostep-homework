
# 概觀

這份作業讓你嘗試幾種在 C 語言中實作一個小型、不會死鎖的向量（vector）物件的方法。
這個向量物件的功能非常有限（例如它只有 `add()` 和 `init()` 兩個函式），
但已足以用來說明幾種避免死鎖的不同做法。

以下是你應該留意的幾個檔案。它們被本作業中所有的變化版本共用：
- `common_threads_zh.h`：對許多不同的 pthread（以及其他）函式庫呼叫的常見包裝，
  用來確保這些呼叫不會悄悄地失敗
- `vector-header_zh.h`：向量相關程式的簡單標頭檔，主要定義了固定的向量大小，
  以及每個向量所使用的結構（vector_t）
- `main-header_zh.h`：所有不同程式共用的一些全域變數
- `main-common_zh.c`：包含 main() 常式（含參數解析），負責初始化兩個向量、
  啟動一些執行緒去存取它們（透過 worker() 常式），然後等待所有的 vector_add() 呼叫完成

本作業的各種變化版本位於以下檔案中。每個檔案針對「向量相加」（vector addition）
常式 `vector_add()` 內的並行處理問題，採取了不同的做法；請檢視這些檔案中的程式碼，
了解其運作方式。它們都會使用上面提到的檔案，組成一個完整可執行的程式。

相關檔案：
- `vector-deadlock_zh.c`：這個版本毫不考慮地依固定順序（先目的地 dst，再來源 src）取得鎖，
  因而製造出一個「死鎖的邀請函」：當某個執行緒呼叫 `vector_add(v1, v2)`，
  同時另一個執行緒呼叫 `vector_add(v2, v1)` 時，就可能發生死鎖。
- `vector-global-order_zh.c`：這個版本的 `vector_add()` 依照向量的記憶體位址，
  以一個全域順序來取得鎖。
- `vector-try-wait_zh.c`：這個版本的 `vector_add()` 使用 `pthread_mutex_trylock()`
  來嘗試取得鎖；當嘗試失敗時，程式會釋放它目前持有的所有鎖，
  然後回到最開頭重新再試一次。
- `vector-avoid-hold-and-wait_zh.c`：這個版本在「取得鎖」的動作外層包上單一個鎖，
  確保自己不會陷入「持有並等待」（hold-and-wait）的情況。
- `vector-nolock_zh.c`：這個版本完全不使用鎖；相反地，它使用原子的 fetch-and-add
  操作來實作 `vector_add()` 常式。因此，它的語意（semantics）也因此略有不同。

輸入 `make -f Makefile_zh`（並閱讀 `Makefile_zh`）來建置這五個可執行檔。

```sh
prompt> make -f Makefile_zh
```

接著只要輸入程式名稱，就可以執行該程式：

```sh
prompt> ./vector-deadlock_zh
```

每個程式都接受相同的一組參數（詳細內容請參考 `main-common_zh.c`）：
- `-d`：這個旗標開啟「讓執行緒發生死鎖」的行為。當你傳入 `-d` 給程式時，
  每隔一個執行緒就會以不同的順序呼叫 `vector_add()`；例如有兩個執行緒且開啟 `-d` 時，
  執行緒 0 呼叫 `vector_add(v1, v2)`，執行緒 1 呼叫 `vector_add(v2, v1)`
- `-p`：這個旗標讓每個執行緒使用不同組的向量來呼叫 add，而不是全部都用同一組（兩個）向量。
  用這個選項可以觀察在沒有相同向量競爭的情況下，程式的表現如何。
- `-n num_threads`：建立指定數量的執行緒；你需要兩個以上的執行緒才有可能造成死鎖。
- `-l loops`：每個執行緒要呼叫 add 幾次？
- `-v`：詳細模式旗標，會印出更多目前執行狀態的資訊。
- `-t`：開啟計時功能，顯示整個程式執行所花費的時間。
