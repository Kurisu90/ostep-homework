
# 概觀

歡迎使用 `ssd_zh.py`，這是 OSTEP 作者們免費提供給大家的另一個模擬器，
而 OSTEP 這本書本身也是免費的。看到這裡，你大概會覺得人生中重要的
東西好像都是免費的！仔細想想，好像還真是如此：你呼吸的空氣、你付出
與得到的愛，還有一本作業系統的書。除此之外你還需要什麼呢？

`ssd_zh.py` 是 `ssd.py` 的中文版本，功能與排程邏輯完全相同，只是把所有
的說明文字、命令列選項說明，以及執行時印出的訊息都換成了中文，方便
閱讀與理解 SSD（Solid State Drive，固態硬碟）的內部運作方式。

要執行模擬器，一樣只要輸入：

```sh
prompt> ./ssd_zh.py
```

這個模擬器模擬了幾種不同類型的 SSD。第一種我們稱之為「理想（ideal）」
SSD，它其實稱不上是真正的 SSD，比較像是一塊完美的記憶體。要模擬這種
SSD，輸入：

```sh
prompt> ./ssd_zh.py -T ideal
```

為了瞭解它是怎麼運作的，讓我們先建立一個簡單的工作負載。對 SSD 而言，
所謂的工作負載，就是一連串發給裝置的低階 I/O 操作。`ssd_zh.py` 支援三種
操作：read（讀取，指定一個要讀取的位址，並傳回資料）、write（寫入，
指定一個位址與要寫入的一個字元資料）、以及 trim（清除，只需要指定
位址）。trim 操作用來標示某個先前寫入的區塊已經不再存活了（也就是說，
它所屬的檔案已經被刪除）；這個操作對日誌式（log-based）SSD 特別有用，
因為它可以在垃圾回收（garbage collection）期間回收該區塊的空間，
釋放 FTL 中的對映項目。讓我們先執行一個只有一次寫入的簡單工作負載：

```sh
prompt> ./ssd_zh.py -T ideal -L w10:a -l 30 -B 3 -p 10
```

`-L` 旗標讓我們可以指定一份以逗號分隔的指令清單。這裡，為了寫入邏輯
分頁 10，我們加入指令「w10:a」，意思是「寫入（write）」邏輯分頁「10」
資料為「a」。我們也用 `-l 30 -B 3 -p 10` 這幾個旗標指定了 SSD 大小的一些
細節，不過先別管這些，晚點再說。

執行以上指令後，你應該會在畫面上看到：

```sh
FTL   （空）
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  iiiiiiiiii iiiiiiiiii iiiiiiiiii 
資料                                   
存活                                   


FTL    10: 10 
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  iiiiiiiiii viiiiiiiii iiiiiiiiii 
資料             a                     
存活             +                     
```

第一段資訊顯示的是 SSD 的初始狀態，第二段則顯示最終狀態。讓我們逐一
檢視每個部分的意義。

每段輸出的第一行顯示 FTL 的內容。這個模擬器只模擬了簡單的分頁對映式
（page-mapped）FTL；因此，其中的每一個項目都顯示了某個存活資料項目的
邏輯到實體分頁對映關係。

在初始狀態下，FTL 是空的：

```sh
FTL   （空）
```

不過，在最終狀態中，你可以看到 FTL 把邏輯分頁 10 對映到實體分頁 10：

```sh
FTL    10: 10 
```

之所以會有這種單純的對映關係，是因為我們執行的是「理想（ideal）」SSD，
它的行為其實就跟一般記憶體一樣：如果你寫入邏輯分頁 X，這個 SSD 就會
（像變魔術一樣）直接把資料寫進實體分頁 X（事實上，這種情況下你根本
不需要 FTL；我們用理想 SSD 只是為了讓你之後比較，看看真正的 SSD
在抹除與資料搬移上要多做多少額外的工作，相較於一塊理想記憶體）。

接下來幾行輸出，只是標示出這個模擬器所模擬的底層 Flash 的區塊
（block）與實體分頁（page）編號：

```sh
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
```

在這個模擬中，你可以看到這個 SSD 有 3 個實體 Flash 區塊，每個區塊有
10 個實體分頁。每個區塊都有編號（0、1、2），每個分頁也有編號
（從 00 到 29）；為了讓顯示畫面保持精簡（寬度上），分頁編號分成兩行
顯示。因此，實體分頁「10」在第一行標示為「1」，第二行標示為「0」。

下一行顯示每個分頁的狀態，也就是課本內文所說的 INVALID（無效，代號 i）、
ERASED（已抹除，代號 E）、或 VALID（有效，代號 v）：

```sh
狀態  iiiiiiiiii viiiiiiiii iiiiiiiiii 
```

「理想」SSD 的狀態顯示起來會有點奇怪，因為同一個區塊裡可能同時混雜
「v」和「i」，而且這個區塊永遠不會是「E」（已抹除）。之後在更貼近
真實情況的「direct」與「log」SSD 中，你就會看到「E」出現了。

最後兩行分別顯示所有被寫入過的分頁的「內容」（Data／資料 那一行），
以及該筆資料目前是否存活（也就是說，是否還被 FTL 參照）（Live／存活
那一行）：

```sh
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
資料             a                     
存活             +                     
```

在這裡，我們可以看到在區塊 2（也就是分頁 10）上有資料「a」，而且它
確實是存活的（用「+」符號表示）。

在正式介紹更貼近真實情況的 SSD 類型之前，讓我們再稍微擴充一下工作
負載。寫入資料之後，我們讀取它，然後再用 trim 把它刪除：

```sh
prompt> ./ssd_zh.py -T ideal -L w10:a,r10,t10 -l 30 -B 3 -p 10
```

如果你執行這個指令，會看到兩個完全相同的狀態：初始（空的）狀態，以及
最終（也是空的！）狀態。不太刺激吧！想看到更多細節，你得再加上幾個
旗標。是的，這個 SSD 模擬器用了非常多旗標；跟所有喜歡簡潔的人說聲
抱歉！但沒辦法，這裡確實有一些複雜度需要我們去探索。

一個好用的旗標是 `-C`，它會顯示每一道發出的指令，以及它是否成功。

```sh
prompt> ./ssd_zh.py -T ideal -L w10:a,r10,t10 -l 30 -B 3 -p 10 -C

FTL   （空）

      0123456789 0123456789 0123456789

      0123456789 0123456789 0123456789

```

在這裡，你可以看到 write、read、trim 三個指令，也可以看到每個指令
傳回的結果：成功、讀到的資料、以及成功。等到之後模擬器隨機產生操作
時，這會變得更有意思。

同樣地，`-F` 旗標會在每次操作之間都顯示一次 Flash 的狀態，而不是只在
最後顯示。留意每一步之間的細微變化：

當然，你也可以同時使用 `-C` 和 `-F`，把所有細節一次看個夠（這就留給
讀者自己練習了）。

這個模擬器也可以幫你隨機產生工作負載，而不用自己指定每一項操作。
使用「-n」旗標並帶一個數字（我們也用「-s」指定一個隨機種子，才能
得到特定的工作負載）：

```sh
prompt> ./ssd_zh.py -T ideal -l 30 -B 3 -p 10 -n 5 -s 10
```

如果你加上 `-C`、`-F`，或兩者都加，就會分別看到確切的指令、Flash
中間狀態，或者兩者都看到。不過，你也可以用「-q」旗標來考考自己，看
你能不能猜出這些指令是什麼。試著執行看看：

```sh
prompt> ./ssd_zh.py -T ideal -l 30 -B 3 -p 10 -n 5 -s 10 -q
（為求簡潔，輸出已省略）
```

現在，藉由檢視中間狀態，看看你能不能推敲出這些指令必定是什麼（write
與 trim 完全不會顯示內容，而 read 只會要求你猜出傳回的是什麼資料）。

你可以自己手動加上 `-C -F` 來顯示所有細節，或者直接加上 `-c` 旗標，讓
模擬器幫你「解題」，用來檢查你的答案。

現在讓我們做同樣的事情（一份包含五個操作的隨機工作負載），但改用
其他更貼近真實情況的 SSD 類型。第一種是課本內文提到的「direct（直接
對映）」SSD。這種 SSD 也不算特別真實，但至少會用到抹除（erase）與
程式化（program）操作來更新 Flash。具體來說，當某個邏輯分頁被寫入時，
它會被直接對映到編號相同的實體分頁。這種對映方式，需要先讀出該區塊
中所有存活的資料，接著抹除該區塊，然後透過一連串的程式化操作，把
原本存活的資料復原回去，同時也把新資料寫入 Flash。讓我們執行它，
顯示指令內容（-C），但不顯示中間狀態（不加 -F）：

```sh
prompt> ./ssd_zh.py -T direct -l 30 -B 3 -p 10 -n 5 -s 10 -C 

FTL   （空）
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  iiiiiiiiii iiiiiiiiii iiiiiiiiii 
資料                                   
存活                                   

cmd   0:: 寫入(12, z) -> 成功
cmd   1:: 寫入(19, 9) -> 成功
cmd   2:: 寫入(9, f) -> 成功
cmd   3:: trim(9) -> 成功
cmd   4:: 讀取(19) -> 9

FTL    12: 12  19: 19 
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  EEEEEEEEEv EEvEEEEEEv iiiiiiiiii 
資料           f   z      9            
存活               +      +            

prompt> 
```

從最終狀態可以看到，FTL 中有兩筆存活對映：邏輯分頁 12 指向實體分頁
12，邏輯分頁 19 指向實體分頁 19（別忘了，這就是所謂的直接對映）。你
也可以看到三個含有資料的實體分頁：實體分頁 9 內容是「f」，12 是「z」，
19 是「9」（資料可以是字母、數字，或任何單一字元）。不過，也要注意
「9」（也就是邏輯分頁 9 的資料）已經被 trim 過了；這會把它從 FTL 中
移除，但資料本身此刻仍靜靜地留在原地（暫時而已）。如果你接著嘗試
讀取邏輯分頁 9，就不會成功了：

```sh
prompt> ./ssd_zh.py -T direct -l 30 -B 3 -p 10 -C -L w9:f,t9,r9

FTL   （空）

區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789

資料           f

```

還有一種我們該注意的 SSD，就是最貼近真實情況的那種：使用日誌式
（log-structured）結構，就跟大部分真實的 SSD 一樣。要使用它，只要把
SSD 類型改成「log」即可（我們一樣打開 -C，這樣就能直接知道發生了哪些
操作，而不用自己猜）：

```sh
prompt> ./ssd_zh.py -T log -l 30 -B 3 -p 10 -s 10 -n 5 -C

FTL   （空）
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  iiiiiiiiii iiiiiiiiii iiiiiiiiii 
資料                                   
存活                                   

cmd   0:: 寫入(12, z) -> 成功
cmd   1:: 寫入(19, 9) -> 成功
cmd   2:: 寫入(9, f) -> 成功
cmd   3:: trim(9) -> 成功
cmd   4:: 讀取(19) -> 9

FTL    12:  0  19:  1 
區塊  0          1          2          
頁面  0000000000 1111111111 2222222222 
      0123456789 0123456789 0123456789 
狀態  vvvEEEEEEE iiiiiiiiii iiiiiiiiii 
資料  z9f                              
存活  ++                               

prompt>
```

留意日誌式 SSD 是怎麼把資料寫進 Flash 的。首先，目前的日誌區塊（在
這個例子中是區塊 0）會先被抹除。接著，各個分頁再依序被程式化寫入。
用 -F 旗標可以看到每一步更詳細的變化。

這個模擬器還可以顯示更多統計資訊，包括操作次數，以及模擬的 SSD
完成整個工作負載所需的估計時間。要看這些資訊，使用 -S 旗標：

```sh
prompt> ./ssd_zh.py -T log -l 30 -B 3 -p 10 -s 10 -n 5 -S

（省略部分內容）

每個區塊的實體操作次數
抹除     1          0          0          總計：1
寫入     3          0          0          總計：3
讀取     1          0          0          總計：1

邏輯操作總計
  寫入次數 3（失敗 0 次）
  讀取次數 1（失敗 0 次）
  trim 次數 1（失敗 0 次）

時間
  抹除時間 1000.00
  寫入時間 120.00
  讀取時間 10.00
  總時間   1130.00
```

在這裡你可以看到每個區塊的實體抹除、寫入、讀取次數，以及各自的
總計，接著是發給裝置的邏輯寫入、讀取、trim 次數，最後則是估計的
時間。你可以用 -R、-W、-E 這幾個旗標分別調整讀取、程式化、抹除等
低階操作的成本。

最後，當 SSD 處於日誌式模式時，還有一個垃圾回收器（GC）可以設定為
週期性執行。這個行為由 -G 與 -g 兩個旗標控制，用來設定判斷垃圾回收器
是否該執行的高、低水位。把高水位設為 N（也就是 -G N）表示，當 GC
偵測到有 N 個區塊正在使用中時，就該執行回收。把低水位設為 M（也就是
-g M）表示 GC 應該持續執行，直到只剩下 M 個區塊在使用中為止。

-J 旗標在這裡也很有用：它會顯示 GC 所發出的每一道低階指令（讀取與
寫入存活資料，接著再抹除已回收的區塊）。以下範例會發出 60 個操作，
並把高、低水位分別設為 3 與 2。

```sh
prompt> ./ssd_zh.py -T log -l 30 -B 3 -p 10 -s 10 -n 60 -G 3 -g 2 -C -F -J
```

同時使用 `-C`、`-F`、`-J`，能讓你一步一步、徹底看清楚日誌式模擬器
內部到底發生了什麼事。

還有幾個值得認識的其他旗標。從頭到尾，我們一直用以下三個旗標控制
模擬 SSD 的大小：

```sh
  -l NUM_LOGICAL_PAGES, --logical_pages=NUM_LOGICAL_PAGES  介面中邏輯分頁的數量
  -B NUM_BLOCKS, --num_blocks=NUM_BLOCKS                   SSD 中實體區塊的數量
  -p PAGES_PER_BLOCK, --pages_per_block=PAGES_PER_BLOCK    每個實體區塊中的分頁數量
```

你可以改變這些數值，來模擬比我們目前所模擬的還要更大或更小的 SSD。

另外還有一組控制項，可以讓你更精確地控制隨機產生的工作負載。`-P`
旗標讓你（機率上地）控制讀取／寫入／trim 各自出現的比例。舉例來說，
使用 `-P 30/35/35` 代表大約 30% 的操作會是讀取，35% 是寫入，35% 是
trim。

`-r` 旗標則允許讀取操作被發送到尚未初始化（非存活）的位址（預設情況
下只會讀取存活的資料）。因此，`-r 10` 代表大約有 10% 的讀取操作會
失敗。

最後，`-K` 與 `-k` 這兩個旗標讓你可以為工作負載加上一些「偏移
（skew）」。偏移首先由 `-K` 指定，例如 `-K 80/20` 代表 80% 的寫入會
集中在 20% 的邏輯空間上（一種冷熱資料混合的工作負載）。這種偏移在
真實的工作負載中很常見，而且對垃圾回收等機制會有不同的影響，因此
能夠模擬這種情況是有幫助的。相關的 `-k` 旗標則可以讓你指定偏移從何時
開始；具體來說，`-k 50` 代表在 50 次寫入之後，才開始套用偏移（在那
之前，寫入的位址會從所有可能的邏輯分頁中隨機選取）。
