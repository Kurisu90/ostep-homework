
# 概觀

歡迎使用 `multi_zh.py`，這是 `multi.py` 的中文版本，功能完全相
同，是一個陽春的多 CPU 排程模擬器，只是把所有的說明文字、命令列選
項說明，以及執行時印出的訊息都換成了中文。這個模擬器有不少可以玩
的功能，請仔細看！或者你也可以偷懶不看，反正你就是這種人。但等到
考試來的時候……

要執行這個模擬器，只要輸入：

```sh
prompt> ./multi_zh.py
```

這樣就會用一些隨機產生的工作來執行模擬器。

在深入細節之前，我們先來看看這種模擬的基本概念。

在預設模式下，系統中會有一顆或多顆 CPU（可以用 `-n` 旗標指定）。所
以，如果你想在模擬中使用 4 顆 CPU，輸入：

```sh
prompt> ./multi_zh.py -n 4
```

每顆 CPU 都有自己的快取，可以存放一個或多個正在執行的行程的重要資
料。每顆 CPU 快取的大小是由 `-M` 旗標設定的。所以，如果你想在 4 顆
CPU 的系統中，讓每個快取的大小都是「100」，執行：

```sh
prompt> ./multi_zh.py -n 4 -M 100
```

要執行一次模擬，你需要一些工作來排程。有兩種方法可以做到這件事。
第一種是讓系統自動幫你產生一些具有隨機特性的工作（這是預設行為，
也就是說，如果你什麼都不指定，就會得到這種結果）；另外也有一些選
項可以（某種程度上）控制這些隨機產生工作的特性，後面會再詳細說
明。第二種方法則是精確指定一份要排程的工作清單，這個做法後面也會
再詳細說明。

每個工作都有兩個特性。第一個是它的「執行時間」（run time，也就是它
會執行多少個時間單位）。第二個是它的「工作集大小」（working set
size，也就是它要有效率地執行，需要多少快取空間）。如果你是用隨機
的方式產生工作，可以透過 `-R`（最大執行時間旗標）和 `-W`（最大工作
集大小旗標）來控制這兩個數值的範圍；隨機產生器接著就只會產生不超
過這些上限的數值。

如果你想自己手動指定工作，可以用 `-L` 旗標明確設定每一項數值。舉
例來說，如果你想執行兩個工作，執行時間都是 100，但工作集大小分別
是 50 與 150，可以這樣做：

```sh
prompt> ./multi_zh.py -n 4 -M 100 -L 1:100:50,2:100:150
```

要注意的是，這裡你幫每個工作都取了名字：第一個工作叫 '1'，第二個
叫 '2'。當工作是自動產生時，名稱也會自動被分配（就是用數字編號）。

一個工作在特定 CPU 上執行的效率，取決於那顆 CPU 的快取目前是否存放
著這個工作的工作集。如果沒有，這個工作就會執行得比較慢，也就是
說，每一個時脈刻度，它剩餘的執行時間只會被扣掉 1 個刻度。這種情況
就是這個工作的快取是「冷」的（也就是快取裡還沒有這個工作的工作
集）。不過，如果這個工作先前已經在這顆 CPU 上執行「夠久」了，這顆
CPU 的快取現在就會是「熱」的，工作也就會執行得更快。你可能會問，
到底會快多少呢？這就要看 `-r` 旗標的值了，也就是所謂的「熱身倍率」
（warmup rate）。這裡預設大概是 2 倍，不過你可以視需要調整。

那快取要花多久才會熱起來呢？這同樣是用旗標設定的，這裡是用 `-w`
旗標，設定「熱身時間」（warmup time）。預設大概是 10 個時間單位。
也就是說，如果一個工作執行了 10 個時間單位，那顆 CPU 上的快取就會
變熱，之後這個工作就會開始跑得比較快。當然，這一切都只是對真實系
統運作方式的粗略近似，不過這正是模擬的美妙之處，對吧？

所以現在我們有了 CPU、各自的快取，還有指定工作的方式。還缺什麼
呢？啊哈，你會說，還缺排程策略！你說得完全正確。真是個認真寫作業
的人，好樣的！

第一種（預設）策略很簡單：使用一個集中式的排程佇列，以輪詢
（round-robin）的方式把工作分配給閒置的 CPU。第二種則是每顆 CPU 各
自使用獨立排程佇列的做法（用 `-p` 開啟），工作會被分配到 N 個排程
佇列中的其中一個（每顆 CPU 一個佇列）；在這種做法下，閒置的 CPU 偶
爾會去偷看其他 CPU 的佇列，並「偷」一個工作過來，藉此改善負載平
衡。多久做一次這樣的動作，是由「偷看」（peek）間隔決定的（用 `-P`
旗標設定）。

有了這些基本概念之後，你現在應該可以開始做作業，研究不同的排程作
法了。要看這個模擬器完整的選項清單，只要輸入：

```sh
prompt> ./multi_zh.py -h
Usage: multi_zh.py [options]

Options:
  -h, --help            show this help message and exit
  -s SEED, --seed=SEED  隨機種子
  -j JOB_NUM, --job_num=JOB_NUM
                        系統中的工作數量
  -R MAX_RUN, --max_run=MAX_RUN
                        隨機產生工作時的最大執行時間
  -W MAX_WSET, --max_wset=MAX_WSET
                        隨機產生工作時的最大工作集大小
  -L JOB_LIST, --job_list=JOB_LIST
                        提供一份以逗號分隔的 job_name:run_time:working_set_size 清單（例如
                        a:10:100,b:10:50 代表 2 個工作，執行時間都是 10，第一個 (a) 的工作集大小是
                        100，第二個 (b) 的工作集大小是 50）
  -p, --per_cpu_queues  每顆 CPU 各自使用獨立的排程佇列（而非共用一個）
  -A AFFINITY, --affinity=AFFINITY
                        指定哪些工作可以在哪些 CPU 上執行的清單（例如 a:0.1.2,b:0.1 代表工作 a 可以在 CPU
                        0、1、2 上執行，但 b 只能在 CPU 0 和 1 上執行）
  -n NUM_CPUS, --num_cpus=NUM_CPUS
                        CPU 的數量
  -q TIME_SLICE, --quantum=TIME_SLICE
                        時間片長度
  -P PEEK_INTERVAL, --peek_interval=PEEK_INTERVAL
                        使用各 CPU 獨立佇列時，多久去偷看一次別的排程佇列；設為 0 代表關閉此功能
  -w WARMUP_TIME, --warmup_time=WARMUP_TIME
                        快取熱身需要花的時間
  -r WARM_RATE, --warm_rate=WARM_RATE
                        快取變熱之後，執行速度會快多少倍
  -M CACHE_SIZE, --cache_size=CACHE_SIZE
                        快取大小
  -o, --rand_order      讓各顆 CPU 以隨機順序取得工作
  -t, --trace           開啟基本追蹤（顯示哪些工作被排入執行）
  -T, --trace_time_left
                        追蹤每個工作剩餘的時間
  -C, --trace_cache     同時追蹤快取狀態（熱/冷）
  -S, --trace_sched     追蹤排程器狀態
  -c, --compute         幫我計算答案
```

（`-h, --help` 那一行是 optparse 套件內建、寫死的英文文字，無法從
程式裡改成中文，因此保留原樣；其餘每一項選項的說明都已翻譯成中
文。）

最值得花時間搞懂的大概是幾個追蹤（tracing）選項（像是 `-t`、
`-T`、`-C` 和 `-S`）。動手玩玩看這些選項，可以更清楚看到排程器與系
統實際上在做什麼。
