
# 總覽

`afs_zh.py` 是 `afs.py` 的中文版本，功能完全相同，只是把說明文字、命令列
選項說明，以及執行時印出的訊息都換成了中文，方便閱讀與理解 AFS
（Andrew File System）的快取一致性（cache consistency）行為。

這個程式讓你可以實驗 Andrew File System（AFS）的快取一致性行為。程式會
產生隨機的用戶端執行記錄（開啟、讀取、寫入、關閉檔案），讓你可以練習
預測最後各個檔案裡會留下什麼值。

以下是一個範例執行：

```sh
prompt> ./afs_zh.py -C 2 -n 1 -s 12

參數 種子 12
參數 用戶端數量 2
參數 步驟數 1
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 
參數 排程 
參數 詳細程度 0

[(1, 'a', 0), (3, 0), (4, 0)]
[(1, 'a', 0), (2, 0), (4, 0)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                            開啟:a [fd:0]
                            寫入:0 數值? -> 1
                            關閉:0
                                                        開啟:a [fd:0]
                                                        讀取:0 -> 數值?
                                                        關閉:0
檔案:a 內容:?
prompt> 
```

（開頭那兩行 `[(1, 'a', 0), ...]` 是程式內部為除錯用途印出的原始動作
清單，來自原始的 `afs.py`，翻譯版同樣保留了這個輸出，並未更動。）

這份執行記錄讀起來相當簡單。最左邊是伺服器，接著每一欄顯示兩個用戶端
各自做了什麼動作（可以用 `-C <用戶端數量>` 指定不同的用戶端數量）。每個
用戶端會隨機產生一個動作（`-n 1`），可能是「開啟／讀取／關閉」某個檔案，
也可能是「開啟／寫入／關閉」某個檔案。為了簡化起見，一個檔案的內容永遠
只是單一一個數字。

要產生不同的執行記錄，一樣可以用 `-s`（隨機種子）。這裡我們把它設成
12，才會得到這個特定的執行記錄。

在這份記錄中，伺服器會先顯示系統中所有檔案一開始的內容：

```sh
檔案:a 內容:0
```

如你所見，系統中只有一個檔案（a），它的內容是 0。

時間往下遞增，接下來是用戶端 0（c0）開啟檔案 'a'（會得到一個檔案描述符，
這裡是 0）、對這個描述符寫入，然後關閉檔案。

馬上你就會看到第一個要回答的問題：

```sh
                            寫入:0 數值? -> 1
```

在對描述符 0 寫入時，你正在把一個既有的值覆寫成新的值 1。那個舊值是
多少？（這題很簡單：0）。

接著用戶端 1（c1）開始動作。它開啟檔案、讀取，然後關閉。這裡又有一個
問題要回答：

```sh
                                                        讀取:0 -> 數值?
```

讀取這個檔案時，用戶端 1 應該會看到什麼值？同樣地，根據 AFS 的一致性
保證，答案很直接：1（也就是 c0 關閉檔案、更新伺服器時放進去的值）。

這份記錄的最後一個問題，是這個檔案最後在伺服器上的值：

```sh
檔案:a 內容:?
```

同樣地，這裡的答案也很簡單：1（由 c0 產生的）。

想知道自己有沒有答對這些問題，可以加上 `-c`（或 `--compute`）旗標執行，
像這樣：

```sh
prompt> ./afs_zh.py -C 2 -n 1 -s 12 -c

參數 種子 12
參數 用戶端數量 2
參數 步驟數 1
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 
參數 排程 
參數 詳細程度 0

[(1, 'a', 0), (3, 0), (4, 0)]
[(1, 'a', 0), (2, 0), (4, 0)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                            開啟:a [fd:0]
                            寫入:0 0 -> 1
                            關閉:0
                                                        開啟:a [fd:0]
                                                        讀取:0 -> 1
                                                        關閉:0
檔案:a 內容:1
prompt> 
```

從這份記錄可以看到，所有的問號都已經被填上了答案。

還可以用 `-d`（`--detail`）旗標看到更多細節。以下範例顯示每個用戶端何時
對伺服器發出 get 或 put：

```sh
prompt> ./afs_zh.py -C 2 -n 1 -s 12 -c -d 1

參數 種子 12
參數 用戶端數量 2
參數 步驟數 1
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 
參數 排程 
參數 詳細程度 1

[(1, 'a', 0), (3, 0), (4, 0)]
[(1, 'a', 0), (2, 0), (4, 0)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                            開啟:a [fd:0]
取得檔案:a c:c0 [0]

                            寫入:0 0 -> 1

                            關閉:0
寫回檔案:a c:c0 [1]

                                                        開啟:a [fd:0]
取得檔案:a c:c1 [1]

                                                        讀取:0 -> 1

                                                        關閉:0

檔案:a 內容:1
prompt>
```

還可以用更高的詳細程度顯示更多資訊，包括快取失效（cache invalidation）
事件、每一步之後用戶端的確切快取狀態，以及額外的除錯資訊。我們會在
下面另一個範例中展示這些內容。

隨機產生用戶端動作很適合用來出題、練習解題；不過在某些情況下，你會
想要精確控制每個用戶端到底做了什麼，藉此觀察 AFS 特定的行為。要做到
這件事，可以使用 `-A` 與 `-S` 旗標（可以分開用，也可以一起用）。

`-S` 旗標可以讓你控制用戶端動作的確切排程。延續上面的範例，假設我們
想先讓用戶端 1 把它的動作全部跑完，可以像這樣執行：

```sh
prompt> ./afs_zh.py -C 2 -n 1 -s 12 -S 111000

參數 種子 12
參數 用戶端數量 2
參數 步驟數 1
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 
參數 排程 111000
參數 詳細程度 0

[(1, 'a', 0), (3, 0), (4, 0)]
[(1, 'a', 0), (2, 0), (4, 0)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                                                        開啟:a [fd:0]
                                                        讀取:0 -> 數值?
                                                        關閉:0
                            開啟:a [fd:0]
                            寫入:0 數值? -> 1
                            關閉:0
                                                        使檔案失效:a 快取: {'a': {'data': 0, 'dirty': False, 'refcnt': 0, 'valid': True}}
檔案:a 內容:?
prompt>
```

這裡的 `-S` 旗標帶的參數是 "111000"，意思是「先跑用戶端 1，再跑用戶端
1，再跑一次 1，然後 0、0、0，如果還沒結束就重複」。這樣的結果是：用戶端
1 會在用戶端 1 寫入檔案 a 之前，先讀取它。

（你會注意到輸出最後那行 `使檔案失效:a 快取: {...}` 其實是 `afs.py`
本身在 `invalidate()` 函式裡的一個除錯用途的原始輸出，並不受 `-d` 旗標
控制、一律都會印出來；這是原始程式本來的行為，翻譯版同樣完整保留。）

`-A` 旗標可以讓你精確控制用戶端要做哪些動作。以下是一個範例：

```sh
prompt> ./afs_zh.py -s 12 -S 011100 -A oa1:r1:c1,oa1:w1:c1

參數 種子 12
參數 用戶端數量 2
參數 步驟數 2
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 oa1:r1:c1,oa1:w1:c1
參數 排程 011100
參數 詳細程度 0

[(1, 'a', 1), (2, 1), (4, 1)]
[(1, 'a', 1), (3, 1), (4, 1)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                            開啟:a [fd:1]
                                                        開啟:a [fd:1]
                                                        寫入:1 數值? -> 1
                                                        關閉:1
                            使檔案失效:a 快取: {'a': {'data': 0, 'dirty': False, 'refcnt': 1, 'valid': True}}
                            讀取:1 -> 數值?
                            關閉:1
檔案:a 內容:?
prompt>
```

在這個範例中，我們用 `-A oa1:r1:c1,oa1:w1:c1` 指定了以下內容。這個清單
用逗號把每個用戶端的動作分開；因此，用戶端 0 要做的是 `oa1:r1:c1` 所
指定的事，而用戶端 1 要做的是字串 `oa1:w1:c1` 所指定的事。解析每個指令
字串的方式很直接：`oa1` 表示開啟檔案 'a' 並將它指定為檔案描述符 1；`r1`
或 `w1` 表示讀取或寫入檔案描述符 1；`c1` 表示關閉檔案描述符 1。

那麼用戶端 0 的讀取會得到什麼值呢？

我們也可以透過幾個額外的旗標（`-d 7`）看到快取狀態、回呼（callback）
與失效（invalidation）事件：

```sh
prompt> ./afs_zh.py -s 12 -S 011100 -A oa1:r1:c1,oa1:w1:c1 -c -d 7

參數 種子 12
參數 用戶端數量 2
參數 步驟數 2
參數 檔案數量 1
參數 讀取比例 0.5
參數 動作 oa1:r1:c1,oa1:w1:c1
參數 排程 011100
參數 詳細程度 7

[(1, 'a', 1), (2, 1), (4, 1)]
[(1, 'a', 1), (3, 1), (4, 1)]
         伺服器                         c0                          c1               
檔案:a 內容:0
                            開啟:a [fd:1]
取得檔案:a c:c0 [0]
                            [a: 0 (v=1,d=0,r=1)]

                                                        開啟:a [fd:1]
取得檔案:a c:c1 [0]
                                                        [a: 0 (v=1,d=0,r=1)]

                                                        寫入:1 0 -> 1
                                                        [a: 1 (v=1,d=1,r=1)]

                                                        關閉:1
寫回檔案:a c:c1 [1]
回呼: c:c0 檔案:a
                            使檔案失效:a 快取: {'a': {'data': 0, 'dirty': False, 'refcnt': 1, 'valid': True}}
                            使 a 失效
                            [a: 0 (v=0,d=0,r=1)]
                                                        [a: 1 (v=1,d=0,r=0)]

                            讀取:1 -> 0
                            [a: 0 (v=0,d=0,r=1)]

                            關閉:1

檔案:a 內容:1
prompt>
```

從這份記錄可以看到，當用戶端 1 關閉（已修改過的）檔案時發生了什麼事。
此時，c1 會把檔案寫回伺服器。伺服器知道 c0 也快取了這個檔案，因此送出
一個失效通知（invalidation）給 c0。不過，c0 這時候已經開啟了這個檔案；
因此，快取會保留舊的內容，直到這個檔案被關閉為止。

你可以透過追蹤整份記錄中的快取內容來觀察這件事（只要 `-d` 的值把第 3
個位元設為 1 就會顯示，例如 `-d 4`、`-d 5`、`-d 6`、`-d 7` 等等）。當
用戶端 0 開啟檔案時，開啟動作結束後你會看到以下的快取狀態：

```sh
                            [a: 0 (v=1,d=0,r=1)]
```

這表示檔案 'a' 在快取中，值是 '0'，並且帶有三個狀態位元：v（valid，
是否有效）、d（dirty，是否被寫過）、r（refcnt，參考計數）。valid 位元
記錄內容是否仍然有效；目前是有效的，因為快取還沒被回呼（callback）
弄失效（還沒被弄失效之前都是有效的）。dirty 位元會在檔案被寫入之後
改變，並且必須在關閉檔案時把內容寫回伺服器。最後，參考計數（reference
count）記錄這個檔案被開啟（但還沒關閉）的次數；這是用來確保用戶端在
所有讀者都關閉檔案、並重新開啟之前，都還能拿到舊的值。

完整的選項清單如下：

```sh
Options:
  -h, --help            show this help message and exit
  -s SEED, --seed=SEED  隨機種子
  -C NUMCLIENTS, --clients=NUMCLIENTS
                        用戶端數量
  -n NUMSTEPS, --numsteps=NUMSTEPS
                        每個用戶端要執行的操作數量
  -f NUMFILES, --numfiles=NUMFILES
                        伺服器上的檔案數量
  -r READRATIO, --readratio=READRATIO
                        讀取與寫入的比例
  -A ACTIONS, --actions=ACTIONS
                        精確指定每個用戶端的動作，例如 oa1:r1:c1,oa1:w1:c1 表示有兩個用戶端；兩者都開啟檔案
                        a，用戶端 0 讀取它，用戶端 1 寫入它，然後兩者都將它關閉
  -S SCHEDULE, --schedule=SCHEDULE
                        要執行的確切排程；01 表示在用戶端 0 與 1 之間輪流（round
                        robin）執行。若不指定則採隨機排程
  -p, --printstats      印出額外的統計資訊
  -c, --compute         幫我計算答案
  -d DETAIL, --detail=DETAIL
                        產生答案時的詳細程度（1:伺服器動作,2:失效事件,4:用戶端快取,8:額外標籤）；可用 OR 運算疊加多種
```

讀完 AFS 那一章之後，回答書末的問題，或者自己動手多玩玩這個模擬器，
增進你對 AFS 的理解。
