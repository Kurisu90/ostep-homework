
# 概觀

這個程式讓你看看在一個使用「分段」（segmentation）機制的系統中，位址轉譯
是怎麼進行的。這個系統所使用的分段方式相當簡單：一個位址空間裡只有
*兩個*區段；此外，行程所產生的虛擬位址的最高位元，會決定這個位址落在
哪個區段：0 代表區段 0（例如程式碼與 heap 通常放在這裡），1 代表區段 1
（stack 住在這裡）。區段 0 朝正方向（也就是朝較高位址）成長，區段 1
則朝負方向成長。

畫成圖大概長這樣：

```
 --------------- 虛擬位址 0
 |    seg0     |
 |             |
 |             |
 |-------------|
 |             |
 |             |
 |             |
 |             |
 |  （未分配）  |
 |             |
 |             |
 |             |
 |-------------|
 |             |
 |    seg1     |
 |-------------| 虛擬位址最大值（位址空間大小）
```

用了分段之後，你應該還記得，每個區段各自有一組 base/limit 暫存器。因此在
這個問題中，一共有兩組 base/limit。區段 0 的 base 代表區段 0 的*頂端*被
放到實體記憶體中的哪個位址，limit 則代表這個區段有多大；區段 1 的 base
代表區段 1 的*底端*被放到實體記憶體中的哪個位址，對應的 limit 同樣代表
這個區段有多大（也就是它朝負方向能成長多遠）。

跟之前一樣，練習這個程式分為兩個步驟。第一步，先不要加上 `-c` 旗標執行，
讓它產生一組位址轉譯題目，看看你能不能自己正確地做出這些位址轉譯。做完
之後，再加上 `-c` 旗標執行一次，用來檢查你的答案。

舉例來說，用預設參數執行：

```sh
prompt> ./segmentation_zh.py
```

或者

```sh
prompt> python ./segmentation_zh.py
```

你應該會看到這樣的內容：

```sh
參數 隨機種子 0
參數 位址空間大小 1k
參數 實體記憶體大小 16k

區段暫存器資訊：

  Segment 0 base（向正方向成長） : 0x00001aea (十進位 6890)
  Segment 0 limit                : 472

  Segment 1 base（向負方向成長） : 0x00001254 (十進位 4692)
  Segment 1 limit                : 450

虛擬位址軌跡
  VA  0: 0x0000020b (十進位:  523) --> PA 或發生分段違規？
  VA  1: 0x0000019e (十進位:  414) --> PA 或發生分段違規？
  VA  2: 0x00000322 (十進位:  802) --> PA 或發生分段違規？
  VA  3: 0x00000136 (十進位:  310) --> PA 或發生分段違規？
  VA  4: 0x000001e8 (十進位:  488) --> PA 或發生分段違規？

對於每一個虛擬位址，請寫下它轉譯後對應的實體位址，
或者寫下它是一個超出範圍的位址（也就是分段違規）。針對
這個問題，你可以假設有一個簡單的位址空間，其中包含兩個區段：
虛擬位址的最高位元可以用來判斷這個虛擬位址落在區段 0（最高位元=0）
還是區段 1（最高位元=1）。請注意，提供給你的 base/limit 組合
會依區段不同而朝不同方向成長，也就是說，區段 0 向正方向成長，
而區段 1 向負方向成長。
```

接著，等你算完虛擬位址軌跡裡每個位址的轉譯結果後，再加上 `-c` 旗標重新
執行一次程式。你會看到以下內容（省略掉重複出現的資訊）：

```sh
虛擬位址軌跡
  VA  0: 0x0000020b (十進位:  523) --> 分段違規（SEG1）
  VA  1: 0x0000019e (十進位:  414) --> 在 SEG0 中合法：0x00001c88 (十進位: 7304)
  VA  2: 0x00000322 (十進位:  802) --> 在 SEG1 中合法：0x00001176 (十進位: 4470)
  VA  3: 0x00000136 (十進位:  310) --> 在 SEG0 中合法：0x00001c20 (十進位: 7200)
  VA  4: 0x000001e8 (十進位:  488) --> 分段違規（SEG0）
```

如你所見，加上 `-c` 之後，程式會幫你把位址都轉譯出來，你就可以檢查
自己是不是真的理解一個使用分段機制的系統是怎麼轉譯位址的。

當然，你也可以透過一些參數，讓自己練習不同的題目。其中特別重要的一個
參數是 `-s`（或 `--seed`），它可以讓你換一個不同的隨機種子，藉此產生
不同的題目。當然，出題跟解題時記得要用同一個隨機種子。

另外還有一些參數可以用來把玩不同大小的位址空間與實體記憶體。舉例來說，
如果想在一個很小的系統上實驗分段機制，可以這樣輸入（實體記憶體至少要
是位址空間大小的兩倍以上，這個模擬器才有辦法自動幫你隨機安排 base
暫存器）：

```sh
prompt> ./segmentation_zh.py -s 100 -a 16 -p 64
參數 隨機種子 100
參數 位址空間大小 16
參數 實體記憶體大小 64

區段暫存器資訊：

  Segment 0 base（向正方向成長） : 0x00000031 (十進位 49)
  Segment 0 limit                : 4

  Segment 1 base（向負方向成長） : 0x00000020 (十進位 32)
  Segment 1 limit                : 5

虛擬位址軌跡
  VA  0: 0x0000000c (十進位:   12) --> PA 或發生分段違規？
  VA  1: 0x00000008 (十進位:    8) --> PA 或發生分段違規？
  VA  2: 0x00000001 (十進位:    1) --> PA 或發生分段違規？
  VA  3: 0x00000007 (十進位:    7) --> PA 或發生分段違規？
  VA  4: 0x00000000 (十進位:    0) --> PA 或發生分段違規？
```

這樣一來，程式就會在一個 64 位元組（byte）的實體記憶體中的某處，放置
一個 16 位元組的位址空間，並產生對應的虛擬位址。如你所見，產生出來的
虛擬位址都非常小（12、8、1、7、0）。你也可以看到，程式挑選的 base
暫存器與 limit 值也相應地非常小。加上 `-c` 執行即可看到答案：

```sh
prompt> ./segmentation_zh.py -s 100 -a 16 -p 64 -c
虛擬位址軌跡
  VA  0: 0x0000000c (十進位:   12) --> 在 SEG1 中合法：0x0000001c (十進位:   28)
  VA  1: 0x00000008 (十進位:    8) --> 分段違規（SEG1）
  VA  2: 0x00000001 (十進位:    1) --> 在 SEG0 中合法：0x00000032 (十進位:   50)
  VA  3: 0x00000007 (十進位:    7) --> 分段違規（SEG0）
  VA  4: 0x00000000 (十進位:    0) --> 在 SEG0 中合法：0x00000031 (十進位:   49)
```

這個例子也能讓你清楚看到每一組 base/limit 分別代表什麼。舉例來說，
區段 0 的 base 被設定在實體位址 49（十進位），大小是 4 個位元組。因此，
*虛擬*位址 0、1、2 落在區段 0 之內且合法，分別對應到實體位址 49、50、
51；而虛擬位址 3 因為超出這個區段的大小（limit 為 4），所以是分段違規。

稍微難懂一點的是朝負方向成長的區段 1。在上面這個小型範例中，程式印出的
「Segment 1 base」是 32（也就是這個區段在實體記憶體中的頂端，加一之後
的位置），limit 是 5 個位元組，所以區段 1 實際佔用的實體位址範圍是
27 到 31。這代表虛擬位址空間*最後*的 5 個位元組——也就是 11、12、13、
14、15——是合法的虛擬位址，並且會依序對應到實體位址 27、28、29、30、
31。如果覺得不好理解，可以多讀幾遍——想解出這些題目，你勢必得先弄懂
這套機制是怎麼運作的。

要注意的是，你可以在傳給 `-a` 或 `-p` 旗標的數值後面加上 `k`、`m`，甚至
`g`，來指定更大的數值，分別代表「千位元組（kilobytes）」、「百萬位元組
（megabytes）」與「十億位元組（gigabytes）」。因此，如果你想在一個 1 MB
的位址空間、32 MB 的實體記憶體中做一些轉譯練習，可以這樣輸入：

```sh
prompt> ./segmentation_zh.py -a 1m -p 32m
```

如果你想要更精確地控制，也可以自己直接指定 base 與 limit 暫存器的值，
分別對應 `--b0`、`--l0`、`--b1`、`--l1` 這幾個選項。動手試試看吧。

最後，你隨時都可以執行

```sh
prompt> ./segmentation_zh.py -h
```

來取得完整的旗標與選項清單：

```sh
Usage: segmentation_zh.py [options]

Options:
  -h, --help            show this help message and exit
  -s SEED, --seed=SEED  隨機種子
  -A ADDRESSES, --addresses=ADDRESSES
                        一組以逗號分隔的頁面，用來存取；-1 代表隨機產生
  -a ASIZE, --asize=ASIZE
                        位址空間大小（例如 16、64k、32m、1g）
  -p PSIZE, --physmem=PSIZE
                        實體記憶體大小（例如 16、64k、32m、1g）
  -n NUM, --numaddrs=NUM
                        要產生的虛擬位址數量
  -b BASE0, --b0=BASE0  segment 0 base 暫存器的值
  -l LEN0, --l0=LEN0    segment 0 limit 暫存器的值
  -B BASE1, --b1=BASE1  segment 1 base 暫存器的值
  -L LEN1, --l1=LEN1    segment 1 limit 暫存器的值
  -c                    幫我計算答案
```

（`-h, --help` 這一行本身是 Python `optparse` 套件內建的說明文字，並非由
這個腳本產生，因此仍會顯示英文原文；其餘所有選項的說明都已翻譯成中文。）

玩得開心！
