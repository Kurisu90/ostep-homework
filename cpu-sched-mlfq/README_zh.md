
`mlfq_zh.py` 是 `mlfq.py` 的中文版本，功能完全相同，只是把所有的說明文字、
命令列選項說明，以及執行時印出的訊息都換成了中文，方便閱讀與理解 MLFQ
（Multi-Level Feedback Queue，多層回饋佇列）排程器的行為。

你可以用它來搭配隨機種子產生練習題，自己動手算出排程結果；也可以用它來
設計特定的實驗，觀察 MLFQ 在不同情境下的表現。要執行這個程式，輸入：

```sh
prompt> ./mlfq_zh.py
```

加上 `-h` 旗標可以看到所有選項：

```sh

Options:
  -h, --help            顯示說明訊息並離開
  -s SEED, --seed=SEED  隨機種子
  -n NUMQUEUES, --numQueues=NUMQUEUES
                        MLFQ 中的佇列數量（若未使用 -Q）
  -q QUANTUM, --quantum=QUANTUM
                        時間片長度（若未使用 -Q）
  -a ALLOTMENT, --allotment=ALLOTMENT
                        允許時長（若未使用 -A）
  -Q QUANTUMLIST, --quantumList=QUANTUMLIST
                        各佇列層級的時間片長度，格式為 x,y,z,...，其中
                        x 是最高優先度佇列的時間片長度，y 是次高優先度
                        的，依此類推
```

這個模擬器有幾種不同的使用方式。第一種是隨機產生一些工作，然後自己
試著算出在 MLFQ 排程器底下它們會如何被執行。舉例來說，若想隨機產生
一個包含三個工作的工作負載，只要輸入：

```sh
prompt> ./mlfq_zh.py -j 3
```

接著你會看到這個具體題目的定義：

```sh
以下是輸入的內容：
選項 工作數量 3
選項 佇列數量 3
選項 佇列  2 的允許時長為   1
選項 佇列  2 的時間片長度為  10
選項 佇列  1 的允許時長為   1
選項 佇列  1 的時間片長度為  10
選項 佇列  0 的允許時長為   1
選項 佇列  0 的時間片長度為  10
選項 boost（優先度提升週期） 0

選項 iobump（I/O 完成後插隊佇列前端） False


每個工作都有三個定義特徵：
  startTime（開始時間）：工作進入系統的時間
  runTime  （執行時間）：工作完成所需的總 CPU 時間
  ioFreq   （I/O 頻率）：工作每執行 ioFreq 個時間單位就會發出一次 I/O
              （這次 I/O 需要花費 ioTime 個時間單位才能完成）

  工作  0：startTime   0 − runTime  84 − ioFreq   7
  工作  1：startTime   0 − runTime  42 − ioFreq   3

如果你願意，也可以順便算出每個工作的
反應時間（response time）與週轉時間（turnaround time）。
```

這份執行記錄以每個時間單位（毫秒）為刻度，精確地顯示排程器實際做了
什麼決定。在這個例子裡，一開始執行工作 0 共 7 個時間單位，直到它發出
I/O 請求為止；這是完全可以預測的，因為工作 0 的 I/O 頻率被設定為 7，
也就是說，每執行 7 個時間單位它就會發出一次 I/O，並且要等 I/O 完成才
能繼續執行。此時，排程器切換去執行工作 1，而工作 1 只執行了 2 個時間
單位就發出了 I/O。排程器就這樣把整個執行記錄逐行印出，最後再算出每
個工作的反應時間與週轉時間，以及它們的平均值。

你也可以控制模擬中的其他各種面向。舉例來說，可以用 `-n` 指定系統中要
有幾個佇列，用 `-q` 指定這些佇列共用的時間片長度；如果想要更精細地
控制、讓每個佇列有不同的時間片長度，可以改用 `-Q`，例如 `-Q 10,20,30`
會模擬一個有三個佇列的排程器，最高優先度佇列的時間片是 10 毫秒，次高
優先度是 20 毫秒，最低優先度則是 30 毫秒。

你也可以分別控制每個佇列的允許時長（allotment）。可以用 `-a` 對所有
佇列設定同一個值，或用 `-A` 個別設定，例如 `-A 20,40,60` 會把三個佇列
的允許時長分別設為 20 毫秒、40 毫秒、60 毫秒。要注意的是，雖然課本內文
是用「時間」來描述允許時長，但在這裡是用「時間片的數量」來表示——也就是
說，如果某個佇列的時間片長度是 10 毫秒，允許時長設為 2，代表這個工作
在該佇列層級最多可以執行 2 個時間片（共 20 毫秒），之後才會被降到較低
的優先度。

如果是隨機產生工作，你也可以控制它們大約會執行多久（`-m`），或多久
會產生一次 I/O（`-M`）。但如果你想要更精確地控制系統中每個工作的細節，
可以使用 `-l`（小寫的 L）或 `--jlist`，直接指定你想要模擬的確切工作
清單。清單的格式為：
`x1,y1,z1:x2,y2,z2:...`，其中 x 是工作的開始時間，y 是執行時間（也就是
需要多少 CPU 時間），z 是 I/O 頻率（也就是每執行 z 毫秒就發出一次 I/O；
如果 z 是 0，代表這個工作完全不會發出 I/O）。

舉例來說，如果想要重現課本圖 8.3 的範例，可以像這樣指定工作清單：

```sh
prompt> ./mlfq_zh.py --jlist 0,180,0:100,20,0 -q 10
```

這樣執行模擬器會建立一個三層的 MLFQ，每一層的時間片都是 10 毫秒。會
建立兩個工作：工作 0 從時間 0 開始，總共需要執行 180 毫秒，且完全不會
發出 I/O；工作 1 從時間 100 開始，只需要 20 毫秒的 CPU 時間就能完成，
同樣完全不會發出 I/O。

最後還有三個值得注意的參數。`-B` 旗標若設為非零值，會每隔 N 毫秒把所有
工作的優先度都提升回最高佇列，用法如下：

```sh
  prompt> ./mlfq_zh.py -B N
```

排程器用這個機制來避免「飢餓」（starvation）問題，這點在課本內文中有
討論過。不過預設情況下這個功能是關閉的。

`-S` 旗標會啟用舊版的規則 4a 與 4b，也就是說，如果一個工作在時間片
用完之前就發出了 I/O，等它恢復執行時，會回到原本那個優先度佇列，並且
擁有完整的允許時長。這會讓排程器有被「鑽漏洞」（gaming）的空間。

另外，你可以用 `-i` 旗標輕鬆調整一次 I/O要花多久時間。在這個簡化模型
中，預設每次 I/O 固定花費 5 毫秒，你也可以用這個旗標改成別的數值。

你還可以用 `-I` 旗標，試試看讓剛完成 I/O 的工作被放到所在佇列的最前面，
還是放到最後面，兩種效果有什麼不同。動手玩玩看，很有意思！
