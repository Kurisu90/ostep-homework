
# 概觀

`relocation_zh.py` 是 `relocation.py` 的中文版本，功能完全相同，只是把說明文字、
命令列選項說明，以及執行時印出的訊息都換成了中文，方便你理解在一個具有
base（基底）與 bounds（界限）暫存器的系統中，位址轉譯是怎麼進行的。

跟之前一樣，練習這個程式分為兩個步驟。第一步，先不要加上 `-c` 旗標執行，
讓它產生一組位址轉譯題目，看看你能不能自己正確地做出這些位址轉譯。做完
之後，再加上 `-c` 旗標執行一次，用來檢查你的答案。

在這份作業中，我們假設的位址空間跟課本內文那種「heap 與 stack 分別位於
位址空間兩端」的經典配置不太一樣。這裡假設位址空間中有一個 code（程式碼）
區段，接著是一個固定大小（很小）的 stack，然後緊接著是一個向下成長的
heap，看起來大致像下圖這樣。在這種配置裡，只有一個成長方向，也就是朝向
位址空間中較高的區域。

```sh
  -------------- 0KB
  |    Code    |
  -------------- 2KB
  |   Stack    |
  -------------- 4KB
  |    Heap    |
  |     |      |
  |     v      |
  -------------- 7KB
  |   (free)   |
  |     ...    |
```

在這張圖中，bounds 暫存器會被設為 7 KB，因為那正是位址空間的結尾。任何
在 bounds 範圍內的位址參照都算合法；超過這個值的參照就是超出範圍，硬體
會因此丟出例外。

要用預設參數執行，只要在命令列輸入 relocation_zh.py 即可。結果應該會像
這樣：

```sh
prompt> ./relocation_zh.py

參數 隨機種子 0
參數 位址空間大小 1k
參數 實體記憶體大小 16k

Base 與 Bounds 暫存器資訊：

  Base（基底）  : 0x00003082 (十進位 12418)
  Limit（界限） : 472

虛擬位址軌跡
  VA  0: 0x000001ae (十進位:  430) --> PA 或發生分段違規？
  VA  1: 0x00000109 (十進位:  265) --> PA 或發生分段違規？
  VA  2: 0x0000020b (十進位:  523) --> PA 或發生分段違規？
  VA  3: 0x0000019e (十進位:  414) --> PA 或發生分段違規？
  VA  4: 0x00000322 (十進位:  802) --> PA 或發生分段違規？

對於每一個虛擬位址，請寫下它轉譯後對應的實體位址，
或者寫下它是一個超出範圍的位址（也就是分段違規）。針對
這個問題，你可以假設有一個給定大小的簡單虛擬位址空間。
```

如你所見，這份作業只是產生了一些隨機的虛擬位址。對每一個位址，你要判斷
它是否在合法範圍內，如果是，還要算出它轉譯後的實體位址。加上 `-c`（也就是
「幫我算」）旗標執行，就能得到這些轉譯的結果，也就是它們是否合法，若合法
的話結果又是什麼。為了方便對照，所有數字都同時以十六進位與十進位表示。

```sh
prompt> ./relocation_zh.py -c

參數 隨機種子 0
參數 位址空間大小 1k
參數 實體記憶體大小 16k

Base 與 Bounds 暫存器資訊：

  Base（基底）  : 0x00003082 (十進位 12418)
  Limit（界限） : 472

虛擬位址軌跡
  VA  0: 0x000001ae (十進位:  430) --> 合法：0x00003230 (十進位: 12848)
  VA  1: 0x00000109 (十進位:  265) --> 合法：0x0000318b (十進位: 12683)
  VA  2: 0x0000020b (十進位:  523) --> 分段違規（SEGMENTATION VIOLATION）
  VA  3: 0x0000019e (十進位:  414) --> 合法：0x00003220 (十進位: 12832)
  VA  4: 0x00000322 (十進位:  802) --> 分段違規（SEGMENTATION VIOLATION）
```

Base 位址是 12418（十進位），位址 430 在合法範圍內（也就是小於 limit
暫存器的 472），因此轉譯結果是 430 加上 12418，等於 12848。上面幾個位址
（523、802）則超出範圍，因為它們超過了 bounds。是不是很簡單？沒錯，這正是
base and bounds 機制迷人的地方——它就是這麼簡單！

還有幾個旗標可以讓你更好地控制這個程式的行為：

```sh
prompt> ./relocation_zh.py -h
Usage: relocation_zh.py [options]

Options:
  -h, --help            show this help message and exit
  -s SEED, --seed=SEED  隨機種子
  -a ASIZE, --asize=ASIZE
                        位址空間大小（例如 16、64k、32m、1g）
  -p PSIZE, --physmem=PSIZE
                        實體記憶體大小（例如 16、64k、32m、1g）
  -n NUM, --addresses=NUM
                        要產生的虛擬位址數量
  -b BASE, --b=BASE     base 暫存器的值
  -l LIMIT, --l=LIMIT   limit 暫存器的值
  -c, --compute         幫我計算答案
```

（`-h, --help` 這行本身是 Python `optparse` 套件內建的說明文字，並不是由
這個腳本產生，所以仍會顯示英文原文，其餘所有選項的說明都已翻譯成中文。）

其中，你可以控制虛擬位址空間的大小（`-a`）、實體記憶體的大小（`-p`）、
要產生的虛擬位址數量（`-n`），以及這個行程的 base 與 bounds 暫存器的值
（分別是 `-b` 與 `-l`）。
