
# 概觀

這個模擬器 `paging-policy_zh.py` 是 `paging-policy.py` 的中文版本，
功能與計算邏輯完全相同，只是把所有的說明文字、命令列選項說明，以及
執行時印出的訊息都換成了中文，方便你嘗試各種不同的分頁置換
（page-replacement）策略。舉例來說，讓我們看看在快取大小為 3 的情況
下，LRU 面對這一連串分頁參照時的表現：

```sh
  0 1 2 0 1 3 0 3 1 2 1
```

執行模擬器的方式如下：

```sh
prompt> ./paging-policy_zh.py --addresses=0,1,2,0,1,3,0,3,1,2,1 \
                              --policy=LRU --cachesize=3 -c
```

你會看到：

```sh
參數 位址清單(addresses) 0,1,2,0,1,3,0,3,1,2,1
參數 位址檔案(addressfile) 
參數 位址數量(numaddrs) 10
參數 置換策略(policy) LRU
參數 時鐘位元數(clockbits) 2
參數 快取大小(cachesize) 3
參數 最大分頁編號(maxpage) 10
參數 隨機種子(seed) 0
參數 不顯示記錄(notrace) False

計算中...

存取：0  失誤 LRU ->          [0] <- MRU 置換:- [命中:0 未命中:1]
存取：1  失誤 LRU ->       [0, 1] <- MRU 置換:- [命中:0 未命中:2]
存取：2  失誤 LRU ->    [0, 1, 2] <- MRU 置換:- [命中:0 未命中:3]
存取：0  命中 LRU ->    [1, 2, 0] <- MRU 置換:- [命中:1 未命中:3]
存取：1  命中 LRU ->    [2, 0, 1] <- MRU 置換:- [命中:2 未命中:3]
存取：3  失誤 LRU ->    [0, 1, 3] <- MRU 置換:2 [命中:2 未命中:4]
存取：0  命中 LRU ->    [1, 3, 0] <- MRU 置換:- [命中:3 未命中:4]
存取：3  命中 LRU ->    [1, 0, 3] <- MRU 置換:- [命中:4 未命中:4]
存取：1  命中 LRU ->    [0, 3, 1] <- MRU 置換:- [命中:5 未命中:4]
存取：2  失誤 LRU ->    [3, 1, 2] <- MRU 置換:0 [命中:5 未命中:5]
存取：1  命中 LRU ->    [3, 2, 1] <- MRU 置換:- [命中:6 未命中:5]

最終統計 命中 6   未命中 5   命中率 54.55
```

（LRU 是「Least Recently Used，最近最少使用」，MRU 則是「Most
Recently Used，最近最常使用」；這兩個縮寫沿用英文原文，沒有特別
翻譯，因為它們本身就是通用的技術術語。）

`paging-policy_zh.py` 完整的參數清單如下，其中包含了改變置換策略、
如何指定或產生位址，以及其他重要參數（例如快取大小）等各種選項：

```sh
prompt> ./paging-policy_zh.py --help
Usage: paging-policy_zh.py [options]

Options:
  -h, --help            show this help message and exit
  -a ADDRESSES, --addresses=ADDRESSES
                        要存取的分頁清單，以逗號分隔；-1 代表隨機產生
  -f ADDRESSFILE, --addressfile=ADDRESSFILE
                        一個內含大量位址的檔案
  -n NUMADDRS, --numaddrs=NUMADDRS
                        若 -a（--addresses）為 -1，這是要產生的位址數量
  -p POLICY, --policy=POLICY
                        置換策略：FIFO、LRU、OPT、UNOPT、RAND、CLOCK
  -b CLOCKBITS, --clockbits=CLOCKBITS
                        CLOCK 策略要使用幾個時鐘位元（clock bits）
  -C CACHESIZE, --cachesize=CACHESIZE
                        分頁快取的大小（以分頁數為單位）
  -m MAXPAGE, --maxpage=MAXPAGE
                        若隨機產生分頁存取，這是最大的分頁編號
  -s SEED, --seed=SEED  隨機數種子
  -N, --notrace         不要印出詳細的執行記錄
  -c, --compute         幫我計算答案
```

跟往常一樣，"-c" 用來把某個特定問題「解出來」；不加這個旗標的話，
程式只會列出各次存取（不會告訴你某次存取究竟是命中還是未命中）。

如果想產生一個隨機的題目，除了用 "-a/--addresses" 直接指定分頁參照
之外，也可以改用 "-n/--numaddrs" 指定要讓程式隨機產生幾個位址，並用
"-s/--seed" 指定不同的隨機種子。舉例來說：

```sh
prompt> ./paging-policy_zh.py -s 10 -n 3
...
假設置換策略為 FIFO，快取大小為 3 個分頁，
請判斷以下每一次分頁參照是命中還是未命中
分頁快取。

存取：5  命中/未命中？  記憶體狀態？
存取：4  命中/未命中？  記憶體狀態？
存取：5  命中/未命中？  記憶體狀態？
```

如你所見，在這個範例中，我們指定了 "-n 3"，也就是要程式隨機產生 3
個分頁參照，而它確實這麼做了：5、4、5（隨機種子指定為 10，正是這個
種子才會產生這幾個特定的數字）。你自己動手算完之後，可以用同樣的
參數再加上 "-c"，讓程式幫你解出正確答案（這裡只列出相關的部分）：

```sh
prompt> ./paging-policy_zh.py -s 10 -n 3 -c
...
計算中...

存取：5  失誤 最早進 ->          [5] <- 最晚進 置換:- [命中:0 未命中:1]
存取：4  失誤 最早進 ->       [5, 4] <- 最晚進 置換:- [命中:0 未命中:2]
存取：5  命中 最早進 ->       [5, 4] <- 最晚進 置換:- [命中:1 未命中:2]

最終統計 命中 1   未命中 2   命中率 33.33
```

（「最早進 / 最晚進」對應 FIFO 策略中先進先出佇列的兩端，也就是英文
原本的 "FirstIn" 與 "Lastin"。）

預設的策略是 FIFO，不過還有其他策略可用，包括 LRU、MRU、OPT（最佳
置換策略，會偷看未來，找出最適合置換的分頁）、UNOPT（最差置換策略）、
RAND（隨機置換），以及 CLOCK（時鐘演算法）。CLOCK 演算法還多接受一個
引數（-b），用來指定每個分頁要保留幾個位元；時鐘位元數越多，演算法
在判斷哪些分頁該留在記憶體中時通常就越準確。

其他選項還包括："-C/--cachesize" 用來改變分頁快取的大小；
"-m/--maxpage" 是模擬器自動產生位址參照時所使用的最大分頁編號；以及
"-f/--addressfile" 讓你指定一個內含位址的檔案，這樣就可以拿真實應用
程式的追蹤紀錄，或其他長度較長的追蹤紀錄當作輸入。

最後來點有趣的：為什麼下面這兩個範例很值得玩味？

```sh
./paging-policy_zh.py -C 3 -a 1,2,3,4,1,2,5,1,2,3,4,5 -c
```

```sh

存取：2  命中 最早進 ->    [1, 2, 5] <- 最晚進 置換:- [命中:2 未命中:7]
```

以及：

```sh
./paging-policy_zh.py -C 4 -a 1,2,3,4,1,2,5,1,2,3,4,5 -c
```

```sh
存取：1  失誤 最早進 ->          [1] <- 最晚進 置換:- [命中:0 未命中:1]
存取：2  失誤 最早進 ->       [1, 2] <- 最晚進 置換:- [命中:0 未命中:2]
存取：3  失誤 最早進 ->    [1, 2, 3] <- 最晚進 置換:- [命中:0 未命中:3]
存取：4  失誤 最早進 -> [1, 2, 3, 4] <- 最晚進 置換:- [命中:0 未命中:4]
存取：1  命中 最早進 -> [1, 2, 3, 4] <- 最晚進 置換:- [命中:1 未命中:4]
存取：2  命中 最早進 -> [1, 2, 3, 4] <- 最晚進 置換:- [命中:2 未命中:4]
存取：5  失誤 最早進 -> [2, 3, 4, 5] <- 最晚進 置換:1 [命中:2 未命中:5]
存取：1  失誤 最早進 -> [3, 4, 5, 1] <- 最晚進 置換:2 [命中:2 未命中:6]
存取：2  失誤 最早進 -> [4, 5, 1, 2] <- 最晚進 置換:3 [命中:2 未命中:7]
存取：3  失誤 最早進 -> [5, 1, 2, 3] <- 最晚進 置換:4 [命中:2 未命中:8]
存取：4  失誤 最早進 -> [1, 2, 3, 4] <- 最晚進 置換:5 [命中:2 未命中:9]
存取：5  失誤 最早進 -> [2, 3, 4, 5] <- 最晚進 置換:1 [命中:2 未命中:10]

最終統計 命中 2   未命中 10   命中率 16.67
```

注意到了嗎？快取從 3 個分頁增加到 4 個分頁，命中次數反而從 3 次
「降低」到 2 次！這正是有名的「Belady 異常（Belady's Anomaly）」：
對 FIFO 這類策略來說，加大快取空間並不保證命中率會變好，有時候
反而會變差。這也是為什麼像 LRU 這種考慮存取歷史的策略，通常比單純
的 FIFO 更受青睞。
